## Goal
The daily gate (`오늘의 관문`, shipped 2026-09-24/25) stands from the first run of every day until passed. Three adjustments, all decided by the user: (1) on a day that has an appointment in the morning, the gate does not stand until 22:00 — the app opens normally before that, home states when the gate will stand and why, and from 22:00 the gate stands as usual and says it was held back; (2) the gate offers one `3시간 미루기` per day, which lifts it for three hours from the tap (never past `23:59`), stamped as a user action and counted in the settings month line; (3) inside the gate, the issue list's minutes, follow-up and schedule rows open read-only sheets, so the user can read what a row refers to without leaving the gate or changing anything. Everything new is either derived at render from the save and the clock, or a stamp of a user action; nothing rewards, pays, completes or moves a grade.

## User decisions (final, 2026-09-26)
1. **Morning-appointment deferral (automatic, derived).** On a day with an appointment in the morning the gate does not stand until **22:00**; from 22:00 it stands as usual until passed. Definition: an occurrence **today** of an event of kind `appt` (`EVENT_KIND_LABEL.appt` = `약속`) with a set `time` (`HH:MM`) **before `12:00`**; an untimed event and a `due` (`마감`) event do not count; a done occurrence (`doneDates` has today) and a cancelled occurrence (`skip` has today) **still count**. No stamp: `gateActiveOf(state, today, nowHm)` becomes time-aware and stays pure ([rule 9](../../design-docs/core-beliefs.md#rule-9)). While deferred the app opens normally; `HomeTab` states beneath the role lines `오늘의 관문 22:00부터 — 오전 약속 {n}건` (`font-mono text-xs text-zinc-400`); from 22:00 the gate adds the line `오전 약속으로 22:00까지 미뤄졌어요`.
2. **Manual deferral.** A gate button `3시간 미루기`, once per day, defers by 3 hours from the tap, capped at `23:59`; stored as `act.gate[today].deferredUntil = "HH:MM"` (a user-action stamp). Afterwards the gate states `{HH:MM}까지 미뤘어요 · 오늘 1회 사용` and the button is gone; while deferred `HomeTab` states `오늘의 관문 {HH:MM}부터 — 미룸`; the settings month line gains `· 미룸 {n}회`. Both deferrals combine as **the later time**. An entry holding only `deferredUntil` counts as not passed.
3. **Read-only viewing during the gate.** Inside the gate's `이슈 목록`, rows become tappable and open a **read-only** variant (`readOnly` prop) of `MeetingViewModal` (no progress form, no follow-up toggles, no split panel, no `수정`, no delete), `DocumentModal` (view only, no edit, no delete) and `EventDetailModal` (no done/cancel/edit, no check add/toggle/delete). Work rows still do not open (they are step 3). `GATE_MODAL_TYPES` admits `meetingView` / `document` / `eventDetail` **only when `readOnly: true`** — the root filter checks the flag. The reader's gate mode and the `다 읽었어요` sentinel are unchanged.

## Planner decisions (recorded here so the implementer does not re-decide)
1. **`nowHm` is root component state, refreshed where `today` already is.** `const [nowHm, setNowHm] = useState(() => hhmm());`; the existing tick's `check` becomes `() => { setDay((d) => (dstr() === d ? d : dstr())); setNowHm(hhmm()); }` (60-second interval, `visibilitychange`, `focus` — no new listener). React skips the render when the string is unchanged, so the cost is one root render per minute; accepted and stated in RELIABILITY. The boot effect and the day-change effect read the clock directly (`hhmm()`), never the state value.
2. **Pure column-0 helpers in the gate block** (smoke lifts them): `morningAppointmentsOf`, `gateDeferredUntil`, `gateActiveOf` (three arguments), `gateDeferTo`, `gateCanDefer`, `gateDeferLine`, `gateAdmits`, plus constants. `gateActiveOf` **fails closed**: with a deferral time and no valid `nowHm`, the gate stands.
3. **Cancelled and done occurrences count**, by the user's definition: `morningAppointmentsOf` expands with `occurrencesOf({ ...ev, skip: [] }, today, today)` (the skip list ignored) and never reads `doneDates`. `eventsOn` is not used for this (it drops cancelled occurrences). `createdAt` is **not** read — an appointment added the same morning also defers (stated as a fact in the docs; see Open risks).
4. **"The later time" is a string comparison** of `HH:MM` values (zero-padded, so lexicographic order is chronological). The morning time is `GATE_MORNING_UNTIL = "22:00"`; the manual one is `deferredUntil`.
5. **The deferral writes through `writeGate`**, so the 60-day prune applies and the entry stays `act.gate[today]`. `deferGate` computes the time from `hhmm()` at the tap (not from the up-to-60-seconds-stale `nowHm`), refuses when the entry already has `deferredUntil`, then calls `setNowHm(hhmm())` and `setModal(null)`. No toast — the gate disappearing, the home line and the gate line afterwards are the statement.
6. **Placement in `GateModal`:** the morning line sits directly under the `오늘 첫 실행 {opened}` line (above the two captions), shown whenever `morningAppointmentsOf(state, today).length > 0` (the gate only renders then from 22:00 on). The manual control sits **directly below `통과`**: the button `3시간 미루기` (`w-full` + `GATE_BTN`, never disabled) while the entry has no `deferredUntil`; otherwise, in the same place, the line `{deferredUntil}까지 미뤘어요 · 오늘 1회 사용` (`font-mono text-xs text-zinc-400`). The captions `세 단계를 마쳐야 앱이 열려요. 닫기와 건너뛰기는 없어요.` and the AI caption stay unchanged (a deferral is neither a close nor a skip).
7. **The home line** is `gateDeferLine(state, today, nowHm)`, rendered by `HomeTab` (new prop `nowHm`) as the last element of its fragment, directly after the role-line ternary: `<p className="px-1 font-mono text-xs text-zinc-400">{line}</p>`, nothing when `null`. When both deferrals apply, the line names the one that decides the time: the morning wording when the result equals `"22:00"` and a morning appointment exists, else the manual wording.
8. **The settings month line always appends** ` · 미룸 {n}회` (including `미룸 0회`), `n` = this month's entries carrying `deferredUntil` (the morning deferral stores nothing and is not counted). A deferral-only entry is counted in `미통과` by the existing rule (entries without `passedAt`).
9. **Settings caption (planner proposal — the main agent confirms or drops it before Phase 1):** the caption `관문은 매일 첫 실행에 열려요. 끄는 설정은 없어요.` stops being accurate. Proposed replacement, facts only: `관문은 매일 첫 실행에 열려요. 오전 약속이 있는 날은 22:00부터 열려요. 하루 한 번 3시간 미룰 수 있어요. 끄는 설정은 없어요.` (flow12 step 10 checks only `끄는 설정은 없어요`, which stays). If dropped, the old caption stays and Phase 3 records the inaccuracy as a tech-debt row.
10. **The root filter becomes one helper call:** `const modal = gateActive && modalRaw && !gateAdmits(modalRaw) ? null : modalRaw;` with `gateAdmits = (m) => !!m && (GATE_MODAL_TYPES.includes(m.type) || (GATE_READONLY_TYPES.includes(m.type) && m.readOnly === true))` and `GATE_READONLY_TYPES = ["meetingView", "document", "eventDetail"]`. `GATE_MODAL_TYPES` itself is unchanged. The `modal.type` count stays 41 (`readOnly` is a flag, not a type).
11. **Rows inside the gate:** `IssueListModal`'s gate-read `openRow` becomes `(spec) => { if (spec && GATE_READONLY_TYPES.includes(spec.type)) onOpen({ ...spec, readOnly: true }); }` — `meeting`, `followUp` and `event` rows and every project card's minutes rows open read-only; `work` and `task` rows stay inert (a task sheet reaches the completion path — rules 10, 18). `{n}건 더` stays plain text. Outside the gate `openRow = onOpen`, unchanged.
12. **Closing a read-only sheet returns to the issue list**, not to the gate: the root passes `onClose={() => setModal(modal.readOnly ? { type: "issues" } : null)}` to the three sheets. The reopened list is in gate-read mode; its read sentinel starts unseen again (an existing `readIssuesAt` is kept — only an unstamped list needs another scroll to the end; stated in the spec).
13. **The read-only variants guard themselves**, independent of the handlers the root passes (the root keeps passing the same handlers; the component renders no control that calls them). Checkboxes that show a state stay visible but `disabled`, with `onChange` kept as a guarded no-op (a controlled checkbox without `onChange` logs a React warning, and 0 console errors is a gate).
14. **`DocumentModal` has no in-gate route today** (`issueListOf` emits no document row; `MeetingViewModal` lists no documents). The variant and its admission are built as decided; no new row is invented. Coverage: smoke (`gateAdmits`) and a throwaway check with a temporary opener; no E2E step can reach it. Recorded as Open risk 1 for the user.
15. **E2E clock control lives in `run.js`** as `h.setClock(hm | null)` (specified in D8), because an `evaluateOnNewDocument` script persists for the page's lifetime; it passes through to the real clock whenever the `sessionStorage` key is absent, so every other flow runs on the real clock. flow12 pins `22:30` for its pre-existing steps, so an appointment left in the save by an earlier flow cannot hold the gate back, and clears the key in its last step.

```js
// runs, so flows that never call setClock are unaffected. A test-only key, never read by the app, never `liferpg-*`.
let clockHooked = false;
const setClock = async (hm) => {
  if (!clockHooked) {
    await page.evaluateOnNewDocument(() => {
      const Real = Date;
      const pinned = () => { try { const v = sessionStorage.getItem("e2e-clock"); return /^\d\d:\d\d$/.test(v || "") ? v : null; } catch { return null; } };
      class ClockDate extends Real {
        constructor(...a) {
          if (a.length) { super(...a); return; }
          const v = pinned();
          if (!v) { super(); return; }
          const d = new Real(); d.setHours(Number(v.slice(0, 2)), Number(v.slice(3, 5)));
          super(d.getTime());
        }
        static now() { return new ClockDate().getTime(); }
      }
      window.Date = ClockDate;
    });
    clockHooked = true;
  }
  await page.evaluate((v) => { if (v) sessionStorage.setItem("e2e-clock", v); else sessionStorage.removeItem("e2e-clock"); }, hm);
};
// A live page re-reads the clock in its focus handler (the app's tick listens to it) — no reload needed.
const tickClock = () => page.evaluate(() => window.dispatchEvent(new Event("focus")));
```
