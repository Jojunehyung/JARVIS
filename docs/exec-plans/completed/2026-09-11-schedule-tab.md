- Agents: planner → implementer → cleanup → verifier → docs-syncer

## Goal
Goals carry a deadline and tasks an optional `due`, but nothing in the app records a real-life event — an interview, an exam date, an application deadline. Add a fifth bottom tab `일정` where events are registered, edited, deleted, ticked off and cancelled per occurrence, each with a date, an optional time and an optional repeat rule, in two kinds: `약속` (leads with its time) and `마감` (leads with its D-day). Events are separate from goals: an event is a record, never a `실행` (task). Today's events and imminent deadlines also appear in the daily briefing, on the home briefing card and in the assistant packet, so all three surfaces state the same facts.

## Prompt
Implement the schedule feature in three phases; every phase ends at the full gate below. An event is **not** a task and not an achievement: it never pays points, never creates a trophy or achievement record, never moves `metrics`, never touches `act.streak`, and never passes through `needsEvidence` — so payouts stay pure ([Rule 1](../../design-docs/core-beliefs.md#rule-1)), metric sources stay as they are ([Rule 8](../../design-docs/core-beliefs.md#rule-8)), the evidence gate is untouched ([Rules 10](../../design-docs/core-beliefs.md#rule-10), [16](../../design-docs/core-beliefs.md#rule-16)) and no `goalId` is required ([Rules 18](../../design-docs/core-beliefs.md#rule-18), [19](../../design-docs/core-beliefs.md#rule-19)). Event code must never call `completeTask`, `tryComplete`, `spawnTask`, `metricsGain`, `needsEvidence`, `detectKind` or `certByTitle`; a certification name inside an event title stays plain text and creates no milestone. Events are excluded from `agendaOf`, `doneTodayCount`, `krProgress`, `goalProgress` and `paceOf`. Repeat occurrences are expanded at render and never written back ([Rule 9](../../design-docs/core-beliefs.md#rule-9)); only the rule plus the user's own `skip` and `doneDates` stamps are stored. Copy is Korean `해요체`, facts and numbers only, and a missed deadline is never hidden or softened ([Rule 13](../../design-docs/core-beliefs.md#rule-13)); identifiers, comments and docs are English (AGENTS §6). Tailwind v3 core utilities only; `store` call sites unchanged; `exportBackup` needs no edit because it serialises the whole state.

Schema v16 ([Rule 12](../../design-docs/core-beliefs.md#rule-12)): append exactly one `if (s.v < 16)` block after the v15 block (`s = { ...s, v: 16, events: s.events || [] }`), bump `v` in `freshState` and give it `events: []`, update the `@schema` JSDoc header and field list, add demo events to `demoState`, and add a v15 → v16 fixture step to `tools/e2e/flow4.js`. Never edit an existing block; `liferpg-*` keys stay.

```js
events: [{ id, title, kind: "appt" | "due", date: "YYYY-MM-DD", time?: "HH:MM", note?, place?,
           repeat?: { freq: "daily" | "weekly" | "monthly", until?: "YYYY-MM-DD" },
           skip?: ["YYYY-MM-DD"], doneDates?: ["YYYY-MM-DD"], createdAt }]
```
Pure helpers next to `agendaOf`: `occurrencesOf(ev, from, to)` returns the occurrence dates inside the window — no `repeat` means `[ev.date]` when in range; `daily` every day; `weekly` on the weekday of `date`; `monthly` on its day of month clamped to the month length (31 → 28/29/30); stops at `repeat.until`, drops `skip` dates, and never iterates more than `MAX_OCC = 400` steps. `eventsOn(state, date)` returns `{ ev, date, done }` with `kind: "due"` first, then `appt` by `time` ascending with untimed last, ties by `title`. `upcomingEvents(state, from, days)` flattens them date-ascending for the tab and the packet. Constants: `EVENT_KIND_LABEL`, `REPEAT_LABEL`, `EVENT_SOON_DAYS = 3`, `EVENT_HORIZON_DAYS = 90`, `EVENT_PAST_DAYS = 30`.

Placement is exact. Nav: `NAV` gains `["schedule", "일정", CalendarDays]` (import the icon from `lucide-react`), `grid-cols-4` becomes `grid-cols-5`, and `ScheduleTab` renders under `tab === "schedule"`. The E2E `clickTab` helper still works because it matches nav button text; `일정` must therefore never be a standalone button label anywhere else — use `일정 추가` and `오늘 일정`.

Acceptance criteria: an event registered with a date and time appears under the right day group with its time; a `마감` event shows `D-n` and a past one `D+n` in rose; a weekly event shows `반복 매주` and appears on the matching weekday of the next weeks; `완료 표시` ticks one occurrence and the button becomes `완료 취소`; `이번 회차 취소` removes only that occurrence and leaves the following ones; editing changes the stored event and re-renders every occurrence; deleting removes it from the tab, the briefing and the packet; `state.events` never gains a derived occurrence array; a v15 save migrates to `v: 16` with `events: []` and every v15 field intact; the fresh save is `v: 16`.
